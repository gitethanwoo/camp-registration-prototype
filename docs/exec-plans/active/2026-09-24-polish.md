## Purpose / Big Picture

The seeded camp season is summer 2028, but the API and the web app read the real wall clock (September 2026). So every live action is stamped 2026 next to seeded 2028 data: a payment made in the demo shows up eighteen months before the camp's registration even opened, "days until camp" counts are huge, and a date picker defaults to 2026. After this plan, the whole product runs on a demo clock that starts at `Demo:Now` (default 2028-03-02 15:00 UTC, the middle of registration season) and moves forward with real time. A presenter sees "today" as March 2, 2028 everywhere: on payments, audit rows, the finance report's default range, and the "last updated" labels.

The same branch closes the small gaps the wave 1 and wave 2 integrations left open:

- Family Camp is published without a waiver, so a family can register without signing anything. It gets a waiver, and the program setup screen (K2) refuses to publish a program that has no waiver.
- Staff pages that need a role (`meta.roles`) open by URL for anyone and then show their own 403. The router now sends a user without the role to `/no-access`, which says which role the page needs.
- After a staff-approved transfer moves one camper of a two-camper order, F1 (family home) and F4 (My registrations) still show the order's original session for both. They now show the moved camper's own session and dates.
- The guest account menu decides once, on page load, whether to show "Applications" and "My groups", so a family's first application doesn't appear there until a reload. It now checks again each time the menu opens.
- David Johnson, Maria's co-owner, becomes a sign-in persona in the WorkOS emulator seed, the README and the e2e fixtures, so the demo can show a second adult landing in the Johnson household.

To see it working: start the API and web app on this branch (commands below), sign in as Maria, and open "My family": the page reads as of March 2, 2028. Sign in as David and land in the Johnson household. Sign in as Diane (CET) and open `/admin/setup/programs`: you land on a "No access" page naming the Administrator role.

## Context and Orientation

The repository is a WinShape camp registration prototype. The API is an ASP.NET Core minimal API in `api/Camp.Api` (EF Core on SQL Server); the web app is Vue 3 with shadcn-vue in `web/`; Playwright specs are in `e2e/`. `AGENTS.md` explains the slice seams: endpoint modules (`IEndpointModule`), seed modules (`ISeedModule`, run on every startup in `Order`), route files under `web/src/features/<slice>/routes.ts`, and the audit log (`IAuditLog`).

A "clock" here means the one source of the current time. .NET has `System.TimeProvider`, an abstract class with `GetUtcNow()`. `api/Camp.Api/Program.cs` registers `TimeProvider.System` as a singleton, but no code injects it yet: about 140 places read `DateTime.UtcNow` directly (seeds, endpoints, the background workers in `Integrations/Workers.cs`, and static helpers such as `FamilyReadModel.Today`, `FinanceShared.Today` and `SetupShared.Today`). On the web side `web/src/lib/clock.ts` exports `now()`, which returns `new Date()`; about ten components still call `new Date()` or `Date.now()` themselves.

Seeded dates are fixed in 2028 (`api/Camp.Api/Data/Seed.cs`: Day Camp June 12–16, 2028; Overnight Camp July 10–15, 2028). Seeded timestamps that are relative ("paid 3 days ago") are computed from the seed's `now`.

Personas sign in through the WorkOS emulator (`infra/workos/workos-emulate.config.yaml`, served on :4100 by docker compose). The e2e helper `signInAs(page, persona)` in `e2e/fixtures.ts` fills the emulator's email box. David Johnson already exists in the seed as an adult in the Johnson household with role "Co-owner" and email `david.johnson@example.com`; sign-in matches him by email (`Auth/AuthEndpoints.cs`, `HouseholdFor`).

Staff routes set `meta.roles` (from `web/src/lib/nav.ts`: `cetRoles`, `financeRoles`, `adminRoles`, matching the API policies in `api/Camp.Api/Auth/Identity.cs`, where admin passes every policy). The router guard in `web/src/router.ts` only checks `meta.auth` today.

A transfer (F8, approved by staff in C10, `Features/StaffCx/TransferService.cs`) moves one `Registration` to another session; the `PaymentOrder` keeps its `SessionId` until every camper on it has moved. F5 (`Features/Family/FamilyRegistrationEndpoints.cs`) already returns `MovedTo` per participant; F1 (`/api/family/overview` in `FamilyEndpoints.cs`, page `web/src/features/family/FamilyHome.vue`) and F4 (`/api/family/registrations`, page `MyRegistrations.vue`) don't.

## Plan of Work

Milestone 1, the API demo clock. Add `api/Camp.Api/Features/Polish/DemoClock.cs`: a `TimeProvider` subclass whose `GetUtcNow()` is the configured anchor plus the real time elapsed since the process started. `Program.cs` registers it in place of `TimeProvider.System`, reading `Demo:Now` (default 2028-03-02T15:00:00Z). `Features/Polish/ClockEndpoints.cs` maps `GET /api/clock` (anonymous; it is not secret) returning `{ now, offsetMs }` where `offsetMs` is the demo time minus the server's real time. Then every `DateTime.UtcNow` / `DateOnly.FromDateTime(DateTime.UtcNow)` read in `api/Camp.Api` becomes a read of the injected `TimeProvider`: endpoint lambdas take a `TimeProvider clock` parameter, services take it in their constructor, seed modules take it in their constructor, and the static `Today` helpers become methods that take the clock. Tests: `ApiFactory` replaces the registration with a `DemoClock` anchored at the same fixed instant, exposes it as `factory.Clock`, and tests that read `DateTime.UtcNow` use `factory.Clock` instead.

Milestone 2, the web demo clock. `web/src/lib/clock.ts` keeps `now()` but adds the server offset, loaded once from `/api/clock` in `main.ts` before mount (falling back to zero offset if the call fails). Every component that reads "now" calls `now()`.

Milestone 3, carry-overs. Finance's seed gives Family Camp a waiver (and backfills it on an existing database). K2's publish path (`Features/Setup/ProgramSetupEndpoints.cs`) refuses to publish, or submit for approval, a program with no waiver, with a specific message. The router guard checks `meta.roles` (the last matched route that sets it) against the session role and redirects to `/no-access?need=staff&role=<label>`; `NoAccess.vue` explains which role the page needs. F1 and F4 return and show a moved camper's own session. `GuestLayout.vue` re-checks Applications and My groups when the menu opens. David is added to the emulator config, README and `e2e/fixtures.ts`.

Milestone 4, proof. `api/Camp.Api.Tests/PolishTests.cs` covers the clock endpoint, stamps from the demo clock, the publish guard (including its authorization), the moved camper on F1 and F4 (and that another household can't see it), and David landing in the Johnson household. `e2e/polish.spec.ts` walks the demo path as David, Maria and Alex/Diane.

## Idempotence and Recovery

Everything here is additive or a like-for-like replacement of a clock read. Seeds stay idempotent: the Family Camp waiver backfill checks for the waiver first. To reset this branch's database, drop `CampRegistration_Polish` and restart the API; it migrates and seeds again. Remove the private emulator with `docker rm -f camp-polish-workos`.
