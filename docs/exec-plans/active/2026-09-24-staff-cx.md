## Purpose / Big Picture

Front-desk staff at WinShape (the Customer Experience Team, "CET") answer calls from families. Before this change the staff console could only list registrations for one session at a time. After it, a CET member such as Diane Carter can type a family name, email, or phone into one search box and find the household in any ministry (screen C1), open a single page that shows everything about that household (C2), approve or reject discount codes that host churches asked for after reading the full rule (C8), review two accounts that look like the same family and merge them without losing a payment plan or a waitlist spot (C9), and approve or deny a family's request to move a camper to another week of the same program (C10). A family can make that request themselves (F8), and their current registration stays confirmed until staff decide. Marcus Reed (Finance) approves discounts that are over the discount threshold.

To see it working: start the API and web app (see Concrete Steps), sign in as Diane, open "Search" in the sidebar, type "Johnson", open the household, then walk Discounts, Duplicates and Transfer requests. Sign in as Maria Johnson, register Avery for Day Camp, open `/family/transfers`, and request a move to June 19–23; sign back in as Diane and approve it.

## Context and Orientation

The repository is a .NET 10 minimal API (`api/Camp.Api`) over SQL Server with EF Core, and a Vue 3 app (`web/`) built from shadcn-vue components in `web/src/components/ui`. Read `AGENTS.md` first; it lists the "seams" a slice uses so it never edits shared files:

- An endpoint module is a class implementing `IEndpointModule` (in `api/Camp.Api/Infrastructure/Modules.cs`); the app finds it by scanning the assembly and calls `Map`.
- A seed module implements `ISeedModule`; it runs after the core seed (`api/Camp.Api/Data/Seed.cs`) on every start, ordered by `Order`, and must check for its own rows first so it is idempotent.
- New tables are mapped with `IEntityTypeConfiguration<T>` classes in the slice folder; `CampDbContext` applies every configuration in the assembly.
- `IAuditLog.Record(action, entityType, id, detail)` stages an audit row; the caller's `SaveChanges` commits it. Every staff mutation calls it.
- Identity: a signed-in family carries a household id claim and resolves `CurrentUser`; staff carry a role claim (`cet`, `finance`, `host`, `admin`) and resolve `StaffUser`. Endpoints use the policies in `api/Camp.Api/Auth/Identity.cs`: `Policies.Staff` (cet, finance, admin), `Policies.Cet`, `Policies.Finance`, `Policies.Family`. The household id is never read from the request.
- Web routes: `web/src/features/<slice>/routes.ts` exports `routes` (guest site children) and `adminRoutes` (children of `/admin`). `meta.nav` adds a sidebar entry; `meta.auth: 'family'` requires a signed-in family.

Money is integer cents everywhere; the web formats with `money()` from `web/src/lib/format.ts`. Seat capacity lives on `CapacityPool` (`Capacity`, `Reserved`), and seats are only ever claimed with a conditional SQL UPDATE (`WHERE Reserved < Capacity`) so the last seat can't be taken twice (see `api/Camp.Api/Features/Checkout.cs`). The status words shown to users are fixed by `docs/product/screen-specs.md` Part 2 (for example "Confirmed", "Waitlisted", "Balance due", "Plan active").

This slice owns `api/Camp.Api/Features/StaffCx/`, `api/Camp.Api.Tests/StaffCxTests.cs`, `web/src/features/staff-cx/`, and `e2e/staff-cx.spec.ts`. It may edit one shared thing: the header "Search families" link in `web/src/layouts/AdminLayout.vue`, which will point at the new search page.

## Idempotence and Recovery

The seed module checks for the June 19–23 session before inserting anything, so restarting the API is safe. Every mutation runs in one SQL transaction; a failed refund or a lost seat race rolls back the whole transfer. Dropping `CampRegistration_StaffCx` and restarting the API rebuilds the demo data from scratch.
